# 架构与兼容性

## 模块

- `LearningCore`：版本化课程模型及资源、假名答案规范化、事件校验与合并、FSRS 重放、学习安排和备份编码。
- `App`：SwiftUI 界面、Core Text 注音、Core Data 事件日志、系统朗读、文档选择和文件协调。
- GitHub Actions：内容校验 → macOS 核心测试 → iOS 持久化与文件交换测试 → 设备归档 → 校验最低系统与课程资源 → IPA artifact。

使用 iOS 15 支持的 NavigationView、ObservableObject 与 Core Data。没有引入要求 iOS 16 的 NavigationStack 或要求 iOS 17 的 SwiftData。

应用通过 `dueKeys` 和 `validateHistory` 使用复习调度；FSRS 的 Card 等类型留在核心模块内部。对外接口只返回本项目定义的类型，避免应用链接时直接依赖传递包的类型元数据。

## 事件与学习状态

日志事件包括复习、单元完成、收藏、笔记与阅读尝试。每个事件有 UUID、设备 UUID、毫秒时间、目标编号及事件内容。Core Data 用事件 UUID 做唯一约束，单批写入事务提交，失败回滚。

复习按 `(知识编号, 技能)` 分开。词汇有读音与词义两个技能，结构题记录表达理解；短文理解单独记录。提示辅助一律按 Again 调度。FSRS 显式选用 21 参数的 FSRS-6，回忆率 0.9，关闭随机间隔抖动，保证同一日志可重放得到相同状态。

事件按时间、设备 UUID、事件 UUID 排序，使用毫秒时间避免备份往返产生精度冲突。相同 UUID、不同内容会拒绝整批导入。未知知识编号继续保留，直到将来课程提供该知识；不把未知项目显示为可复习卡片。

收藏及笔记取排序后的最后一次事件。取消收藏写 `false`，清空笔记写空字符串，因此旧备份不会使已删除内容复活。单元完成取并集。时间排序依赖设备时钟，跨设备使用前应开启系统自动日期时间。

## 学习中断

本机 session checkpoint 保存完整任务、当前位置、提示使用记录和每项的固定事件 UUID。顺序为：先将答案事件提交数据库，再原子保存新位置。选择题在选择时立即提交答案，“继续”时前移位置；若在二者之间退出，下次进入根据已经提交的事件 UUID 前移。同一答案不重复计数；使用提示后暂停，再次进入仍按辅助回答处理。

Checkpoint 只在本机保存。同步的是学习记录，另一台设备可以安排自己的练习。每次开始新的今日安排都会重新检查当天首次引入的词与表达，避免通过重复开始绕过每日新词配额。已有词缺少的另一技能仍可补练。

## 备份与目录交换

`.jplearnbackup` 和 `.jplearnsync` 均采用同一封装：JSON 包含 SHA-256 校验值和 Base64 编码的原始 payload。校验针对精确字节；payload 包含格式标识 `dev.jplearn.events`、schema version 1、课程版本、创建时间及事件。

目录交换过程：

1. 解析本机保存的目录 bookmark，获得 security-scoped 访问。
2. 在后台任务中枚举不可变事件文件；通过 NSFileCoordinator 读取并验证。iCloud 文件未落盘时请求下载，显示待下载数量。
3. 验证所有可读取记录，与本机事件求并集；校验失败不导入、不写新批次。
4. 本机已知但目录中尚未出现的事件写入 UUID 文件名的新批次，采用协调写入和原子文件替换。
5. 回到主线程，将合并事件事务提交。交换过程中新增的本机答案继续保留。

同步目录授权、声音选择、每日时长和 session checkpoint 不跨设备同步。未承诺持续后台同步或有界云端传输延迟。界面“已与文件夹交换”只表示本次本地文件交换结束。

当前每次交换读取日志，重放也以完整日志为准，优先保证正确性。大规模历史下可增加可丢弃缓存、分段索引和快照压缩；优化必须保留事件合并与重放测试，不能直接同步 SQLite 文件。

## 版本与发布边界

首次实现没有 CloudKit 容器或开发者账号要求。发布自有 CloudKit 后端属于独立迁移，不能复用其他应用的容器身份。

固定 Bundle ID 以保留侧载更新的数据。切换 Bundle ID 会产生独立安装，应通过备份迁移。更改调度参数前为新的事件定义 scheduler version，并保留历史版本的重放路径。
